# Roadmap

Планируемые улучшения и доработки проекта, сгруппированные по тематическим разделам.

## MQTT Core

- **Повторная передача неподтвержденных сообщений** — `RetransmitTask` периодически проверяет и повторно отправляет неподтвержденные MQTT сообщения с помощью `ThreadPoolTaskScheduler`, `PeriodicTrigger`.
- **Хранение неподтвержденных MQTT сообщений** — сохранять сообщения, для которых не получено подтверждение от брокера.
- **Поддержка TLS** — защищенное подключение к брокеру.
- **Поддержка MQTT wildcards** — для сокращения количества правил.
- **Использование строк-шаблонов (`%VALUE%`)** — пересылка данных настраивается через маску `payloadTemplate` (например, `{"status": "%VALUE%"}`). Веб-панель может управлять любым IoT устройством без изменения Java-кода.
- **Проверка соединения при подписке** — в `HmMq2tImpl` в методе `subscribe` добавить проверку `isConnected`.
- **Обработка существующей сессии** — после коннекта перед подпиской проверять `sessionPresent`; если сессия есть, то `subscribe` не вызывать.
- **Потокобезопасный генератор ID** — переделать `getNewMessageId` с учетом многопоточности: `id = this.nextMessageId.updateAndGet(current >= 0xffff) ? 1 : current + 1)`.
- **Сигнализация о понижении QoS** — если на топик не удалось подписаться или брокер понизил QoS, сигнализировать об этом и корректировать список подписок.
- **Таймаут подписки** — в `SubscriptionService`: `Promise<MqttSubAckMessage> promise = mediator.subscribe(prepared);` если вышел `connectTimeout` (`promise.awaitUninterruptibly(this.connectTimeout)`), устанавливать promise в failure.

## Модель данных и подписки

- **Свойство актуального QoS** — в entity (или в `SubscriptionService`) у подписок добавить свойство, сигнализирующее о понижении QoS брокером.
- **Новые сущности `Subscriptions` и `Publications`** — записывать актуальный QoS после подписки; в карточках хранить ссылку на entity. Создать таблицы `Subscriptions` и `Publications`.
- **Переименование полей карточек** — переименовать `subscriptionDataName`, `subscriptionDataType`, `publicationData` и т.п. в отображаемые названия (или аналогичные).

## Хранение данных

- **Перенос файлов БД и логов** — перенести в `userHome`.
- **Таблица триггеров** — для выполнения команд и заданий.
- **Хранение графиков** — например, температуры и т.п.

## Планировщик

- **Планировщик `CronTrigger`** — запуск скриптов, опрос датчиков и т.п. по расписанию с использованием маски звездочек `CronTrigger`.

## UI / Отображение

- **Рефакторинг форматтера** — `Base64HtmlJsonFormatterImpl` разделить на JSON и HTML; `JsonFormatter` переименовать в `jsonpathutil`.
- **Тип `uiType` для карточек** — ввести тип для управления отображением.
- **Внешний фреймворк для контролов** — вынести контролы в отдельный фреймворк.

## Технический долг

- **Заменить билдер на record** — использовать `record` вместо билдеров.
- **Virtual Threads** — перенастроить Spring на `virtualThreads`.
